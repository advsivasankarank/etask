# e-Tasks System Admin Guide

## Purpose

This guide is for system administrators responsible for installation, environment setup, backups, migration control, access provisioning, and release governance.

## Core Responsibilities

- maintain application configuration
- manage database connectivity
- run schema migrations
- create backups before changes
- provision users and roles
- validate environment health
- monitor logs and document storage

## User and Permission Administration

### Internal user administration

- create internal users from `Users`
- assign one or more internal roles
- reset passwords when required
- archive instead of deleting

### Portal user administration

- portal users are linked to `client_contacts`
- create from `Users` or CRM-supported portal user flow
- only `CLIENT` role is valid for portal users

### Permission model

- permissions are granted through `role_permissions`
- user-specific overrides can be granted through `user_permissions`
- route access is enforced using permission middleware

## Application Controls

### No delete policy

- records are archived, not deleted
- final closed workflows are locked
- document downloads are audited

### Document security

- all document downloads must use `/documents/{id}/download`
- new uploads are stored in `PRIVATE_STORAGE_PATH`
- access checks include authentication, ownership, and permission evaluation

### Financial controls

- invoice numbering is generated by sequence tables
- receipt numbering is generated by sequence tables
- disbursements roll into invoices
- final closure remains blocked when consultant payment is pending

## Monitoring

Check these locations regularly:

- `storage/logs/`
- `storage/backups/`
- `storage/reports/regression/`
- private storage path configured by `PRIVATE_STORAGE_PATH`

## Routine Operating Cycle

### Daily

- verify application login
- review error logs
- check reminder scheduler execution
- confirm backup completion

### Before deployment

- run backup
- confirm migration status
- run environment doctor
- run regression suite

### After deployment

- verify login
- verify Users, Clients, Service Orders, Billing, Reports, Search, Documents, and Reminders
- review logs for runtime exceptions

## Incident Response

If a deployment or migration causes issues:

1. stop further changes
2. restore last backup if necessary
3. restore previous code package
4. rerun environment doctor
5. retest core modules

## RC1 Governance

- schema is frozen at RC1
- permissions are frozen at RC1
- routes are frozen at RC1
- any changes after RC1 should be tracked as post-RC change requests
